# 红迹·延安 —— AI 问答讲解员与分享卡

> IP：延安（延安全域，18 处旧址与场馆）
> 一句话：扫码就能问延安的历史，回答带可核查的来源，问完生成一张问答卡带走。
> 全部自建：一个 Python 文件起服务，不依赖任何第三方智能体平台。

**在线体验（临时隧道，进程关闭即失效）**：`docs/PUBLIC_URL.txt` 里的地址，或直接扫 `二维码.png`。

---

## 一、怎么跑

```bash
python run.py --port 8788          # 只需要 Python 3.9+，零第三方依赖
# 浏览器打开 http://127.0.0.1:8788
# 手机与电脑连同一 Wi-Fi，扫终端打印的局域网地址（或二维码.png 换成局域网地址重新生成）
```

换地址重新生成二维码：

```bash
python tools/make_qr.py https://你的地址
```

## 二、它做了什么

| 能力 | 实现 | 约束 |
|---|---|---|
| 回答问题 | 50 条带来源问答 + 实体优先检索 + 打分 | 低于阈值直接拒答，不猜 |
| 标来源 | 每条回答挂 `[Sxx]`，点开是机构、文件、日期、原文链接 | 一条回答最多 3 个来源 |
| 三种输出 | 史实问答 / 研学讲解词 / 朋友圈一句话 | 同一份事实，三种说法 |
| 生成问答卡 | Canvas 现画：提问、摘要、来源、二维码 | 可保存 PNG、可复制文案 |
| 口径冲突 | 两种官方说法都列，注明“不合并、不平均” | 例：馆藏 3.5 万 vs 11 万余件 |
| 知识库热更新 | 页面每 45 秒比对 `/api/kb` 版本号 | 变了就换库并提示，不打断用户 |
| 断网兜底 | `web/kb.js` 内嵌整库 | 纯静态托管、无服务也能用 |

## 三、目录

```
hongji-yanan/
├─ run.py / server.py        # 服务：静态页 + /api/kb + /api/log + /api/selftest
├─ server.py                 # （标准库 ThreadingHTTPServer）
├─ web/
│  ├─ index.html style.css   # 手机端界面
│  ├─ engine.js              # 检索与作答引擎（浏览器 / Node 共用）
│  ├─ app.js                 # 交互、来源抽屉、问答卡
│  └─ kb.js                  # 自动生成的知识库内嵌副本
├─ data/
│  ├─ kb.json                # 运行时知识库（50 条 / 27 个来源）
│  ├─ kb_health.json         # 27 个来源的联网校验记录
│  └─ usage.jsonl            # 问答日志（问句/模式/命中/是否拒答）
├─ build/                    # 生成器：kb_spec → 知识库 → 六份文档
├─ tools/
│  ├─ selftest.js            # 命中率 / 同义问法 / 越界拒答 / 时延
│  ├─ check_dom.js           # 前端接线自检
│  ├─ sync_kb.py             # 来源联网校验（--watch 可定时）
│  └─ make_qr.py             # 生成二维码
└─ 01—08 号参赛文档与表格
```

## 四、自测结果（可复跑）

```bash
node tools/selftest.js     # → docs/selftest.json
node tools/check_dom.js    # → 前端 id 接线
python tools/sync_kb.py    # → data/kb_health.json
```

| 指标 | 结果 |
|---|---|
| 知识库 | 50 条 / 27 个来源 |
| 自身问法命中 | 50 / 50 |
| 同义问法命中 | 16 / 16（“七大在哪开的”“壶口门票多少钱”） |
| 越界提问 | 13 条直接拒答 + 2 条命中拒答样板，1 条误命中（见局限） |
| 单次作答时延 | 约 0.1 ms（离线检索） |
| 来源可达性 | 27 / 27 可打开（2026-10-29 校验） |

**已知局限**（写在 `08_自测报告.docx`）：概念类问题（“红色旅游的定义”）会误命中数据条目；只覆盖 50 条；没有接大模型，三种模式是模板改写。

## 五、知识库怎么更新

1. 改 `build/kb_spec.py` 里的问答（每条必须有 `ref` 或 `extra` 来源）；
2. `python build/build_kb.py` → 重写 `data/kb.json` 与 `web/kb.js`，版本号自动变；
3. 页面 45 秒内热更新，游客不用刷新。

联网校验只写 `data/kb_health.json`，不改知识库内容，所以「校验过」不会无谓改版本号。

## 八、真实性说明

所有史实来自延安市人民政府、延安市文化和旅游局、中国政府网、文化和旅游部、国家文物局、新华社、人民网、光明网、央视网、陕西日报等公开页面，逐条记录机构、文件、发布日期与链接。来源冲突时并列呈现（如枣园进驻时间 1943.10 与 1944 两种官方口径），不合并、不平均。未核实的数据（如梁家河的票价与开放时间）不进知识库，只回答“没有官方公开文件，不推测”。
